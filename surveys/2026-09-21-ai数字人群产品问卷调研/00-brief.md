# 调研简报：AI数字人群产品问卷调研

## 用户问题

做一个 AI 数字人的调研：用 AI 技术构建数十万种人群，模拟不同性格、年龄、职业等属性的人类，用虚拟人群做产品问卷调查，了解市面上可借鉴的开源技术。

## Superpowers Brainstorming 门

- Status: Assumed
- Notes: 用户已给出核心场景、规模方向和技术兴趣。本轮先做公开资料与开源项目核验，不把“数十万 persona”直接等同于“数十万独立、可信的调查样本”。

## 需要做出的决策

判断该方向应采用哪种产品定义和技术路线：是做大规模合成研究平台、真实用户研究的预筛选工具，还是把 AI 人群当作真实问卷样本的替代品；并筛选可复用的开源底座。

## 研究镜头

- 技术可行性：persona 建模、记忆、行为模拟、批量推理与评测。
- 开源采用：项目成熟度、许可证、扩展方式、是否有真实用户研究证据。
- 产品与方法有效性：模拟回答是否能解释真实市场选择，哪些问题适合/不适合。
- 风险与验证：模型偏差、同质化、隐私、伦理、可复现性和真实样本校准。

## 研究框架

- Framework Profile Router：主要采用“技术可行性 + 开源采用 + 产品机会 + 信任/研究有效性”复合框架。
- 主要决策原型：技术可行性与开源采用。
- 辅助决策原型：产品机会、研究有效性、信任风险。
- 选定 lens packs：open-source、workflow、technical、policy/trust。
- 行业/领域提示：产品调研/市场研究，结果可能影响定价、产品路线和发布决策。
- 曾考虑但拒绝的 profile：单纯的多智能体框架盘点；因为“能运行 agent”不代表“能产生有效调查数据”。
- 为什么该 profile 适合本决策：它同时覆盖底层工程、研究方法和可商业化交付，不会只按 GitHub 热度选型。
- Framework Contract：
  - 需要覆盖的维度：规模与成本、persona 与行为、仿真环境、问卷工作流、验证与校准、开源可采用性、风险与产品边界。
  - 否决性维度：无法证明许可可用、无法批量运行、无法进行真实样本校准、或将合成数据包装为真实用户事实。
  - 章节权重：研究有效性 25%，工程规模与成本 20%，开源可采用性 20%，产品工作流 15%，风险与治理 15%，前沿差异化 5%。
  - 有意排除的维度：本轮不做完整竞品定价调查，不推断任何项目的未来融资或商业成功。
- Evidence Contract：
  - 按维度列出的最低直接证据：每个候选项目至少查官方仓库/论文/文档中的定位、架构、运行方式和许可证；关键有效性主张需要论文或真实实验。
  - 按维度列出的优先来源类型：官方 GitHub、论文原文、官方文档、许可证文件、项目作者技术报告；媒体仅作线索。
  - 按维度列出的反证证据：失败复现、低相关性、同质化、规模成本、许可证限制、项目停更或仅 demo。
  - 不能替代直接证据的材料：GitHub star、博客宣传、单个漂亮 demo、模型自评和没有真实用户对照的准确率数字。
  - 决策关键变量：每个 persona 的状态成本、每个问卷问题的推理成本、persona 间有效差异、与真实样本的相关性、可解释性、许可和数据治理。
  - 隐含预期反推：用户可能期待用低成本合成样本替代大部分真人调研；本轮必须验证这一强预期是否成立。
  - 按约束分层建议：若只能内部探索，可先用小规模校准；若对外宣称洞察或替代真人样本，必须通过真实样本基准测试。
  - 反叙事正则项：不把“数十万”当成产品价值，不把 agent 数量当成样本量，不把框架热度当成研究有效性。

### 规模与成本

核心问题：数十万是静态 persona 数据库、可按需激活的对象，还是同时运行的 agent？需要证据：批量推理、状态存储、调度和成本机制。薄弱点：公开项目很少证明数十万 agent 同时运行。

### Persona 与行为

核心问题：属性、记忆、偏好、性格如何转化为稳定且有差异的回答？需要证据：persona schema、记忆机制、行为规则和跨轮一致性评测。薄弱点：随机提示词通常造成表面差异，不能证明行为有效。

### 仿真环境与问卷工作流

核心问题：项目是否支持多轮问卷、条件分支、实验对照、聚合和导出？需要证据：官方示例、API、任务编排能力。薄弱点：许多社会仿真项目面向开放世界，而不是产品问卷。

### 验证与校准

核心问题：合成回答与目标市场真人回答的相关性如何测量？需要证据：论文、真实数据对照、外部验证和失败案例。薄弱点：无真实样本对照就无法判断市场研究价值。

### 开源可采用性

核心问题：哪些仓库可作为生产底座？需要证据：许可证、活跃度、文档、依赖、部署方式和扩展接口。薄弱点：研究代码可能不适合商业生产。

### 风险与产品边界

核心问题：如何避免把合成意见误报为真实民意，并处理偏见、隐私和敏感属性？需要证据：论文局限、许可证、治理设计和行业规范。薄弱点：用户可能将成本优势误解为证据等价。

## 决策证据标准

- Mode: standard
- Minimum Sources: 3
- Minimum Claims: 3
- Minimum Evidence Items: 3
- Target Report Length: 1,500-3,500 words
- Quality Gate: standard standalone report; continue while desk-researchable unknowns remain

## 决策框架完整性

- 用户原始框架：构建数十万种 AI 虚拟人，用于产品问卷调查，并寻找可借鉴的开源技术。
- 已知事实：只有目标场景和规模意图，尚无目标客户、预算、行业、问卷类型和真实性指标。
- 隐含/未验证假设：AI persona 能代表真实消费者；属性组合能产生真实行为差异；数十万规模会提高洞察质量；合成样本可替代真人。
- 主观判断：尚未确认是否接受“辅助研究”而非“替代研究”的产品定位。
- 缺失信息：目标市场、问题类型、允许误差、预算、延迟、是否对外出具结论、是否涉及敏感属性。
- 关键利益相关方：产品经理、市场研究团队、品牌方、真实受访者、被建模人群、合规/法务团队。
- 重述后的目标：判断能否构建一个可扩展、可校准、可解释的合成消费者研究系统，并确定其可靠边界和最小可行验证方案。
- 互相竞争的目标：规模 vs 成本、个性化 vs 可控性、回答丰富度 vs 可验证性、速度 vs 真实样本校准。
- 对象质量 vs 行动吸引力：一个优秀的仿真框架不等于值得采用；一个低成本 demo 不等于可信研究产品。
- 硬约束：不能把合成回答冒充真人回答；商业使用须核验许可证；关键结论须有真实样本基准。
- 软约束：低延迟、支持中文、云端部署、可解释、可按需扩展。
- 用户特定约束：关注开源技术借鉴；期望数十万级人群。
- 缺失约束：实际预算、模型供应、数据合规边界。
- 隐含预期：希望显著降低问卷调研成本并缩短周期。
- 不应优化的方向：单纯追求 persona 数量、agent 数量、回答字数或 GitHub 热度。
- 原始问题已保留：是；只是把“能不能替代真人”拆成待验证命题。
- 支持的决策框架：以“合成研究辅助工具”作为默认可行方向，以“真人样本替代品”作为高证据门槛方向。
- 未预设更强命题：没有假设合成数据必然有效，也没有因存在偏差就直接否定全部用途。
- 允许收窄的依据：若直接证据显示缺少真实样本相关性，可将首版收窄为预筛选、假设生成和问卷优化。

## 决策优化合约

- 原始问题：做 AI 数字人群产品问卷调研，并寻找开源技术。
- 重构后的目标函数：在给定模型成本、时间和治理约束下，最大化合成研究对真实产品决策的增量信息，而不是最大化虚拟人数量。
- 候选行动：A. 直接做数十万并发 agent；B. 做可按需激活的 persona 池并用真人样本校准；C. 先做问卷预筛选/假设生成工具；D. 暂不做，继续使用真人研究。
- 不行动 / 等待 / 继续调研选项：先完成项目和论文核验，再用小规模真人 A/B 基准决定是否扩张。
- 硬约束：许可证可用、数据来源合规、结果标明合成性质、关键决策保留真人验证。
- 硬约束通过条件：小规模实验中可复现，且预设指标达到真人基线的明确阈值。
- 阻断性硬约束：不能完成真实性校准或无法解释模型偏差。
- 软约束：成本、响应速度、中文能力、工程复杂度。
- 软残差权重：研究有效性最高，其次是规模成本和开源维护性。
- 缺失约束：预算与目标行业需要后续确认。
- 成功标准：能定义 persona schema，批量运行问卷，输出分层结果和不确定性，并在真实样本上验证相关性。
- 失败标准：只能生成互相不同的文本，却无法预测真实选择；或规模成本抵消真人调研收益。
- 机会成本：投入大规模 agent 基础设施可能延误真实用户访谈和小样本问卷。
- 可逆性：首版小规模实验可逆；建立数十万并发基础设施不可逆成本较高。
- 隐含预期：合成数据能降低研究成本并加快迭代。
- 隐含预期反推：必须同时测量成本、周期、预测能力和决策命中率。
- 当前行动、价格或选择隐含：尚未指定。
- 这些预期需要的证据：真实产品问题上的真人对照实验，而非通用 benchmark。
- 决策关键变量：校准相关性、模式同质化、单位问题成本、有效样本数、可解释性、许可证和治理。
- 最低直接证据：至少 3 个开源候选的官方资料，至少 1 个合成社会/消费者仿真的有效性研究，至少 1 个反方或局限证据。
- 按约束分层建议：内部探索可先做 C；面向企业交付应采用 B；A 只有在 B 的校准结果和成本曲线成立后再考虑。
- 能改变决策的证据：在目标行业真人基准上达到预设相关性，或出现无法通过校准修复的系统性偏差。

## 目标客户

首要客户假设为产品经理、增长团队和市场研究团队；首版更适合有持续产品迭代、能提供历史问卷/行为数据进行校准的团队。

## 成功标准

形成一份带原始链接的开源项目短名单、技术架构建议、适用和不适用场景、验证实验设计，以及是否值得进入 MVP 的条件判断。

## 放弃条件

若公开证据表明候选开源技术都无法支持可按需扩展和真实样本校准，则放弃“合成样本替代真人”的定位，改为研究辅助工具或停止投入。

## 初始假设

- 数十万 persona 应主要是可压缩的结构化档案，按需激活，而非全部常驻推理。
- persona 需要由人口属性、价值观、偏好、记忆和行为生成器共同定义。
- 真实样本校准比扩大 persona 数量更能提升产品价值。
- 开源底座可能需要组合，而不是寻找一个完整解决方案。

## 继续策略

- 先完成第一轮开源项目、论文和官方资料核验。
- 若仍存在可通过公开资料解决的关键问题，继续下一轮聚焦规模/成本或真实性校准。
- 只有当关键桌面研究不确定性已不足以改变行动建议时，才进入最终报告。
