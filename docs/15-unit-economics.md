# 单位经济模型与定价建议(docs/14 §77)

> 2026-09-19。基于当前真实成本结构(青果代理/AgentBay/GLM/SAE)推算每 run 成本,
> 评估现行定价的毛利,给出调价与限额建议。数字为估算,上线前用 admin 成本报表校准。

## 1. 单次采集 run 的变动成本

| 成本项 | 计费方式 | 单 run 估算 | 说明 |
|---|---|---|---|

辅助:报告生成(行业洞察/行动项/品牌挖掘)每份 3–6 次 GLM 调用 ≈ ¥0.05–0.15,周更可忽略。

## 2. 各套餐的采集成本上限

按 questionQuota(ranking+reputation)× 引擎数 × 日采频率(保守按隔日有效):

| 套餐 | 月费 | 题量配额 | 引擎 | 日 run 上限 | 月成本(隔日) | 毛利率 |
|---|---|---|---|---|---|---|
| starter ¥79 | 20 | 3 | ¥13.5–34 | **亏损风险** |
| standard ¥199 | 50 | 5 | 125 | ≈ ¥1,900–4,700 | **严重亏损** |
| pro ¥499 | 150 | 5 | 375 | ≈ ¥5,600–14,000 | **不可售** |

> 结论:**standard 以上档位在"每日全量采集"假设下成本远超月费**。当前线上没有爆单,
> 是因为账号池(40–60 run/日)物理封顶了消耗——成本被供给侧意外压住,而不是定价合理。

## 3. 建议方案(三选一或组合)

**方案 A(推荐):限量不限频 + 覆盖率承诺**
- 套餐改为按"月度有效 run 数"计:starter 600 / standard 2,000 / pro 6,000(成本 ¥60–500,毛利 25–65%)。
- 页面承诺"覆盖度"(如 standard 每题每周至少 3 引擎×1 次),把价值锚从"每天采"转为"稳定覆盖"。
- 调度配合公平算法(已上线):先保证每周覆盖,再追求日更。

**方案 B:提价**
- standard ¥499 / pro ¥1,299,保持日采。风险:对标透镜GEO(¥399 档)失去价格带。

**方案 C:降频默认 + 高频加购**
- 默认每题每 3 天一轮(成本÷3),日更作为 ¥99/月加购包。
