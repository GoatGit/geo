# 02 · 指标体系与口径

本文档是产品的"方法论宪法"：所有指标的定义、分母规则、阈值与展示规则以本文为准。指标名使用行业通用概念，口径定义为自有版本。

## 1. 采集口径基础

### 1.1 原子查询（QueryRun）

`查询任务 = 监控问题 × 引擎 × 端(网页/APP) × 轮次`。一次采集轮次（Round）中，每个组合产生一条 QueryRun。

**四态状态机（教训 #5 对策）**：

| 状态 | 定义 | 计入分母？ |
|------|------|-----------|
| `ok_with_answer` | 成功返回含正文回答 | ✅ |
| `ok_empty` | 成功返回但无实质回答（模型拒答/无结果） | ✅（视为"未提及"） |
| `failed` | 采集失败（超时/风控拦截/解析异常） | ❌ 不计入分母 |
| `quota_blocked` | 配额/余额不足未执行 | ❌ |

> 分母规则：`分母 = ok_with_answer + ok_empty`。任何页面展示指标时必须可查看 failed/quota_blocked 数量——**不允许"失败静默变成 0"**。

### 1.2 排名判定

AI 回答中推荐实体列表的抽取规则（详见 05 文档）：

- 回答若给出有序推荐列表，按列表序记录品牌位次（1-based）。
- 回答为散文式提及（无明确列表）：记 `mentioned=true`，位次记为 `null`（不参与名次均值，计入提及率）。
- **提及判定**：命中识别口径（识别词或任一别名，命中后归一为品牌）。别名表由识别口径管理模块维护。
- 每条判定保留证据：命中词、命中片段、在原文中的位置，供下钻与审计。
- **判定层（2026-09-18 修订）**：识别由 Insight Agent（LLM）执行——语义级判定（变体/代称/语境）替代字符串匹配；上列位次/证据/口径规则不变。规则匹配引擎降级为 Insight Agent 不可用时的 fallback 路径（降级判定置信度压 0.5,自动进人工抽检池），详见 docs/09。

### 1.3 综合名次（引擎×问题矩阵行尾聚合列）

单问题在单轮次内跨引擎聚合为一个"综合名次"（N = 该问题本轮实际参采引擎数）：

1. **归一化**：各引擎位次中，`未上榜`（含散文式提及、无列表位次）记为 `N+1`；
2. **聚合**：取 N 个归一位次的**中位数**（偶数个时取中间两值的算术平均并向上取整——评价偏保守）；
3. **语义**：综合名次 ≤ N 表示"多数引擎进入推荐列表"；= N+1 表示"全线出局或仅散文提及"；
4. **平局与展示**：矩阵内同分按各引擎位次均值升序、再按首推引擎数排序；行尾同时展示三率，综合名次仅用于排序与趋势；
5. **固化**：综合名次随 `daily_metrics` 按日固化，驱动"综合排名趋势"折线（05 §4）。

> 校验样例（与竞品实测对照，research 02 §5.2）：某问题各引擎位次 未上榜/#3/未上榜/#5/#1，N=5，归一后 [6,3,6,5,1]，中位数 = 5 → 综合 #5，与竞品展示一致，且口径可解释。

## 2. 核心指标定义

| 指标 | 定义 | 分母 | 展示要求 |
|------|------|------|----------|
| 提及率 Mention Rate | 品牌被提及的 QueryRun 占比 | 有效 QueryRun 数 | 始终展示分子/分母，如 29/40 |
| Top3 率 | 品牌位次 ≤3 的 QueryRun 占比 | 有效且有名次的 QueryRun | 与提及率分母不同，需标注 |
| 首推率 | 品牌位次 =1 的占比 | 同上 | 同上 |
| 平均名次 | 有名次 QueryRun 的位次均值 | 有名次的 QueryRun | 值越小越好；无列表式提及不计入 |
| 情绪得分 | 正面占比 ×100（见 §4） | 口碑词有效 QueryRun | 0-100 |
| 竞争位次 | 按提及率在竞品榜中的排名 | 竞品榜 | #N |
| 自有信源引用数 | 引用链接归属自有域名的条数（衍生口径：自有信源引用占比 = 自有被引 ÷ 总被引） | — | 绝对值 + 占比 |

### 可见性漏斗（自研核心视图）

三段全部使用**嵌套转化口径**（每段分母 = 上一段的分子集合），杜绝"跨分母拼漏斗"导致的倒挂：

| 段 | 指标 | 分子 | 分母 |
|----|------|------|------|
| ① 提及 | 提及率 | `mentioned=true` 的 QueryRun | 全部有效 QueryRun（ok_with_answer + ok_empty） |
| ② 上榜 | 上榜转化率 | 位次 ≤3 的 QueryRun | ①分子（被提及的 QueryRun） |
| ③ 首推 | 首推转化率 | 位次 =1 的 QueryRun | ②分子（进 Top3 的 QueryRun） |

```
有效查询 100%
 └─ 提及 73%              → 损失：未被提及（内容未进入候选池 / 问题类型不适配）
     └─ 上榜 82%（24/29）   → 损失：被提及但未进 Top3（列表权威性不足，含散文式提及）
         └─ 首推 96%（23/24） → 损失：进 Top3 但非首位（首因内容竞争力）
```

- 单调性由嵌套集合保证（②③恒 ≤100%）；散文式提及计入 ② 的分母——"被提及但进不了推荐列表"本身就是 GEO 要解决的损失，不应被隐藏；
- 指标卡仍按 §2 行业口径展示提及率/Top3 率/首推率（分母不同），漏斗视图旁标注转化口径，两套数字并用、口径徽章可查；
- 每段损失可点击下钻到具体问题清单，行动清单（§6）据此生成。

## 3. 健康阈值与体检标签

阈值**可配置**（品牌级默认继承平台默认）。

**阈值确定方法（自有方法论）**：行业分位数法——达标线取平台沉淀的行业分布 **P75**（即跑赢 75% 的同行业品牌），每 8 周随分布重校一次，校准日期与依据在报告方法论附录公示。首轮上线尚无自有分布时，采用下表初始值（数值与行业常见水位对齐）；灰度期（前 8 周）标签旁标注"阈值校准中"。

初始默认：

| 指标 | 达标线 | 低于达标线标签 |
|------|--------|----------------|
| 提及率 | ≥ 85% | 需提升 |
| Top3 率 | ≥ 60% | 需提升 |
| 首推率 | ≥ 60% | 需提升 |
| 平均名次 | ≤ 2.0 | 需提升 |
| 情绪得分 | ≥ 60 | 需关注 |
| 自有信源引用占比 | 自有域名被引条数 ÷ 总被引条数 ≥ 8%（且 ≥10 条） | 话语权薄弱 |

体检总览输出"N 项达标 · M 项需提升"，逐项附口径与证据入口。

## 4. 口碑口径

- 适用范围：仅口碑词问题。
- **情感三分类**：对每个有效 QueryRun 的回答全文判定 正面/中性/负面，输出得分 = round(正面数/有效数 × 100)。
- **印象词**：从回答中抽取与品牌关联的评价性短语，去重后按"词种"计数（不是出现次数）；正面词归入"优势印象"，负面词归入"待攻印象"，各展示 TOP6。统计窗口 = 报告周期（周报/月报对应自然周/自然月）；同义归并表（如"贵/溢价高/价格高"→"价格高"）人工维护、随 parserVersion 入库，保证跨期可比。
- 每个印象词必须可点开查看 ≥1 条原文摘录（证据链要求）。
- 模型抽取置信度 < 阈值的判定进入人工抽检池（见 05 文档 §3.4）。
- **判定层（2026-09-18 修订）**：情绪与印象词由 Insight Agent（LLM）判定——否定/转折按语义处理,竞品吐槽不误伤本品,印象词为短语级。LLM 高置信（≥0.9）判定写 `auditState='auto'` 免抽检,其余入池。词库规则降级为 fallback,详见 docs/09。

## 5. 问题分层（位次诊断）

按"进入 Top3 的引擎占比"给监控问题分层（N = 该题参采引擎数），驱动行动优先级：

| 层 | 定义 | 解读 |
|----|------|------|
| L1 全线领先 | N/N 引擎进 Top3 | 守住：内容保鲜即可 |
| L2 多数上榜 | ≥60% 且 <N（5 引擎时即 3-4 个） | 巩固：补短板引擎 |
| L3 少数上榜 | ≥1 且 <60% | 补位：内容重写/渠道建议 |
| L4 全线缺席 | 0/N | 攻坚：候选池收录问题，优先排查引用源覆盖 |

N < 3 的问题不参与分层（样本不足，显示"样本不足"），避免小参采面问题误判层级。

## 6. 行动清单（规则引擎，替代竞品的 AI Agent）

确定性规则产出 P0/P1/P2 建议，每条含：动作 + 数据依据 + 目标值。规则集初始版本：

| 优先级 | 触发规则 | 建议动作（模板） |
|--------|----------|------------------|
| P0 | 存在 L4 问题 | 排查引用源覆盖；针对该问题补结构化事实内容 |
| P0 | 首推率 < 60% 且 Top3 率 ≥ 60% | 对已上榜问题做内容前置优化（首因段抢占） |
| P1 | 某引擎三率显著低于均值（差 > 15pct） | 针对该引擎取材偏好定向布局（引用缺口地图联动） |
| P1 | 竞对在某平台类型被引次数 ≥ 3× 我方 | 建议在该类平台补充结构化内容 |
| P2 | 情绪得分 < 60 | 针对 TOP 待攻印象产出事实澄清内容 |
| P2 | 负面印象词含"价格/服务"类 | 官网与服务渠道补价格、售后结构化信息 |

规则版本化管理（规则集 ID 记录进报告），保证报告可复现。

| 档位 | 月价 | 问题数（排名词+口碑词分池） | 网页引擎 | APP 端 | 频率 | 备注 |

| 专业 | ¥499 | 100 + 30 | 5 个 | ✅ | 每日 1 轮 | 优先队列、多品牌(≤5) |
| 定制 | 面议 | 自定 | 自定 | 自定 | 自定 | API 输出 |

年付：3 个月 8 折 / 12 个月 7 折。

### 7.2 积分（Credit）

- 定价基准：¥0.1/积分，充值 100 积分起。
- 消耗项：快速体检（网页端查询 2 分/问题·引擎，APP 端 4 分，APP 端高成本引擎 8 分）；历史数据导出（10 分/次）；报告 PDF 加急（20 分/次）。
- **所有消耗入口必须显式标注积分数值**（教训：竞品仅显示图标，用户点击才知道成本）。
- 积分流水全量留存（充值/消耗/退款/过期），对账以流水为准。

## 8. 数据展示一致性原则（教训 #2 对策）

1. 全平台**单一指标服务**（Metrics Service）供数，任何页面不允许自行聚合原始表。
2. 卡片级时间戳：每个指标卡标注"数据截至"，精确到采集轮次完成时间。
3. 周期选择器默认规则：优先"今日（含进行中轮次，标记'部分数据'）"→ 无数据回退"最近完成日"→ 无任何数据显示引导态 + 预计完成时间。
4. 日快照（T+1 固化）仅用于趋势线与报告；实时页与快照页的数据来源在页面角落标明（"实时" / "日结"徽章）。
