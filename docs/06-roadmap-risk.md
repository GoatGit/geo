# 06 · 路线图、成本与风险

## 1. 里程碑

### M0 · 可信 MVP（第 1-10 周）
目标：**10 分钟内让新用户看到真实排名数据**，单引擎全链路打通。
- 网页端 3 个引擎适配器（1 个网络捕获路线 + 2 个 DOM 路线），经 AgentBay `browser_latest` CDP 会话采集（PoC 验证清单见 07 §13）
- 品牌初始化（含识别口径 AI 建议）、监控问题管理（分类+拓写）
- 排名透视：指标卡（分子/分母）+ 榜单 + 引擎×问题矩阵
- 快照存证（截图 + 原文 + 7 天保留）、采集状态页
- 免费版 + 入门版订阅、手机验证码登录
- 验收：40 QueryRun 轮次 ≤ 10 分钟；引擎成功率 ≥ 95%；指标可下钻到原文

### M1 · 完整监测面（第 11-20 周）
- 5 引擎全量 + 竞品透视（含自动发现与待确认池）
- 引用源管道 + 追溯/信源偏好 + 缺口地图
- 口碑分析（含抽检校准闭环）
- 周报/月报 + PDF 导出；标准/专业档 + 积分体系
- APP 端通道（1-2 个引擎先行；AgentBay 云手机镜像 vs 自建云真机农场，P1 启动前完成评估）

### M2 · 商业化放大（第 21-30 周）
- 快速体检（估价器 + 支付 + 只读分享报告）
- Agency 多品牌 + 成员权限 + 报告去品牌化
- 引用洞察环比、自定义健康阈值、API 输出（定制档）

## 2. 团队与工作量估算

| 角色 | M0 | M1 | M2 |
|------|----|----|----|
| 全栈/前端 | 2 | 2 | 2 |
| 后端 | 2 | 3 | 3 |
| 采集/反爬专项 | 1 | 2 | 2 |
| 产品/设计 | 1 | 1 | 1 |
| 运营（账号池/渠道供给） | 0.5 | 1 | 1 |

M0（10 周，6.5 人）≈ 60-65 人周；M1（10 周，9.5 人）≈ 90-95 人周，其中采集/反爬专项 2 人为**持续投入，不是一次性工程**（页面改版响应、账号池补给、风控策略迭代），MVP 起就需固定人力。SAE + AgentBay 形态下无"采集节点运维"角色，基础设施人力集中在可观测性与成本哨兵。

## 3. 成本模型（月度，v2 部署形态 SAE + AgentBay；M1 规模假设：300 活跃品牌 × 日均 60 查询 ≈ 54 万 QueryRun/月，配额使用率假设 60%）

| 项 | 月成本估算 |
|----|-----------|
| SAE（web/api/worker 三应用） | ¥1k-2k |
| AgentBay 权益包（Pro/Ultra，CDP 端点前置） | ¥1k-1.5k（固定） |
| AgentBay 会话积分（≈¥0.6/会话小时 × 0.7-1.3 万会话小时） | ¥4k-8k |
| 代理 IP（住宅包月+流量） | ¥3k-8k |
| 账号供给（注册/接码/封损） | ¥5k-20k（波动最大） |
| RDS/Redis/OSS/SLS/监控 | ¥2k-4k |
| LLM 解析（批量小模型） | ¥2k-5k |
| 云手机（APP 端，P1，按开通量） | ¥0k-20k |
| **合计（不含 APP 端）** | **≈ ¥1.8万-4.9万/月** |

**单位经济核对**（网页端单查询全口径）：会话 ¥0.007-0.02 + 代理 ¥0.01-0.03 + 账号摊销 ¥0.02-0.08 + LLM ¥0.01-0.03 ≈ **¥0.05-0.16/次**。订阅档位满配月用量成本对照（使用率 100% 口径）：入门 1,500 次 ≈ ¥75-240 vs 定价 ¥79；标准 5,700 次 ≈ ¥285-912 vs ¥199；专业 19,500 次 ≈ ¥975-3,120 vs ¥499（**2026-09 定价决策：专业版取消"每日 2 轮"，全档位每日 1 轮**）。**结论：整体打平需同时满足"配额使用率 ≈60%、免费→付费转化率 ≥8%、账号月封损率 ≤15%"三项假设，任一失守即触发定价/配额复审；标准/专业档毛利仍偏薄，积分加购与历史导出等增值项是主要对冲**。免费版单品牌成本 ≈ ¥10-15/月（9 查询/日 × 30 天），设免费总量闸门（名额上限 + 每账号限 1 个免费品牌），不再使用"总成本 10%"口径。

## 4. 合规与风险

### 4.1 采集手段风险（最高优先级）
- **事实**：账号池模拟访问与 APP 自动化通常违反目标平台用户协议；存在民事（不正当竞争）与技术对抗双重风险。
- **缓解**：①仅采集公开问答结果、不破解付费接口、不绕过技术保护措施的技术红线由法务划线；②账号与自然人身份隔离，不留存可回溯到自然人的信息；③对外叙事强调"独立第三方、不干预排名、过程存证可审计"；④准备降级方案：部分引擎切换到官方 API（标注口径差异）。
- **决策要求**：M0 启动前完成法务评估并形成"引擎-手段"白名单。

### 4.1.1 用户侧与内容侧合规（v2 新增）

- 域名 **ICP 备案**（短信登录前置条件，签名/模板报备同期办理）；上线后启动**等保二级**定级备案；
- **PIPL**：手机号收集的告知同意、账号注销与数据删除流程、个人信息处理规则公示；
- 《人工智能生成合成内容标识办法》：对外分享的报告引用 AI 生成的回答原文/截图，需完成 **AI 生成内容标识**评估并在分享页落标；
- 以上与 07 文档 §10 保持同步，由法务清单统一跟踪。

### 4.2 技术风险
| 风险 | 影响 | 对策 |
|------|------|------|
| 页面/接口频繁改版 | 单引擎数据中断 | 适配器版本化 + Mock 回放测试集 + 2 人专项快速响应；多引擎冗余降低单点影响 |
| 账号封损率超预期 | 成本失控 | 健康分自动冷却、拟人化节奏、多注册渠道；封损率纳入周报 |
| LLM 抽取质量漂移 | 口径失真 | 抽检校准闭环 + parserVersion 重放 |
| 数据被质疑 | 信任崩塌 | 全链路存证 + 分子/分母透明 + 失败/空分离，这是产品对抗质疑的根本 |

### 4.3 市场风险
- 竞品已有先发数据资产与渠道资源；我方差异化：**口径透明度、识别口径管理（防误判）、空态/失败态诚实呈现、更清晰的配额语义**——把竞品被实测暴露的 6 个弱点（00 文档 §4）做成宣传点。
- 引擎官方 API 未来开放程度提升可能降低采集壁垒 → 提前布局"多源口径对照"能力（API 口径 vs 模拟口径差异分析），把威胁变成功能。

## 5. 验收口径（对齐"复刻神"的定义）

M1 结束时须全部满足：
1. 任意指标 → 3 次点击内到达原始回答与快照证据；
2. 任意品牌初始化 → 自家产品别名进入识别口径（无"自家当竞品"误判路径）;
3. 采集失败/配额拦截在任何页面都不体现为 0 值；
4. 新品牌从注册到首轮真实数据 ≤ 10 分钟；
5. 单查询全口径成本（会话+代理+账号+LLM）≤ ¥0.2/次（网页端），账号月封损率 ≤ 15%；
6. 报告（周/月）自动生成成功率 ≥ 99%，可复现（规则版本入库）。
