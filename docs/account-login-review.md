# 账号池登录审查（2026-09-18）

本次检查覆盖后台账号池、登录 API、Worker 编排、浏览器代理，以及登录态交给采集任务的过程。以下问题已在工作区修复。

| 严重性 | 问题与影响 | 修复 |
| --- | --- | --- |
| P1 | 登录等待中每 15 秒重新导航，手机号、验证码、二维码确认流程被打断 | 未登录时保留页面，仅在已有登录凭证且需要返回聊天页时导航 |
| P1 | 豆包游客输入框可见、弹窗关闭也可能被判为成功，浏览器提前关闭 | 人工登录要求正向凭证、输入框可见、连续确认和重新导航验证 |
| P1 | DeepSeek 登录令牌存于 localStorage，只保存 Cookie 导致新采集会话丢失令牌 | 保存并恢复包含 Cookie、各 origin localStorage 的 storageState |
| P1 | 输入指令 LPUSH/LPOP 倒序执行，文字可能在点击输入框之前发送 | 改为 RPUSH/LPOP，前端串行发送操作 |
| P1 | 本地默认无头模式用于人工登录，操作者没有窗口；空闲采集浏览器也会被复用 | 人工登录按 viewer 开关选择窗口；切换用途重新启动，活动登录与采集互斥 |
| P1 | 同一账号可重复登录；成功写库可能覆盖停用状态；浏览器尚未持久化就进入可用池 | 每档案登录锁、条件更新、浏览器释放后才入池 |
| P2 | 阻塞队列消费与截图/指令共用 Redis 连接，交互被阻塞 | 使用独立阻塞消费连接 |
| P2 | 远程画面仅支持点击，无法人工拖动滑块；高像素密度截图可能偏移 | 增加拖动、滚动、全选、Tab，截图使用 CSS 像素 |
| P2 | 刷新后台丢失会话、一次网络失败就停止轮询、取消请求立即解除忙碌状态 | 恢复活动会话、临时故障继续轮询、等待 Worker 返回终态 |
| P2 | 旧 Cookie 优先于登出 URL，空值 Cookie 也算有效 | 先判显式登出/登录页、限制站点 origin、拒绝空 Cookie |

## 证据与验证

- 用全新 Chrome 上下文访问当前官网：DeepSeek 未登录跳转 `/sign_in`；豆包游客聊天页保留输入区和登录入口。
- 检查 DeepSeek 公开前端代码及游客 localStorage：`userToken` 为 AppKit 存储项，当前格式包含 `value` 与 `__version`，游客值为 null。没有读取或记录真实账号令牌。
- 新增 21 项回归测试，覆盖登录证据、等待/取消、保存失败、停用冲突、浏览器用途、指令顺序与采集恢复。
- 用真实 Chrome 和受控页面验证 storageState 跨上下文恢复；用后台页面和模拟 API 验证点击坐标、拖动、输入顺序、发送失败保留文字、刷新恢复、网络重试与取消。
- 新迁移在临时 PostgreSQL 16 上执行两次，确认幂等。
- 原仓库已有两项无关失败：`packages/shared/test/platform-settings.test.ts` 和 `apps/api/test/insight-admin.test.ts` 仍断言洞察超时上限 30 秒，HEAD 实现已为 60 秒。本次未改动该行为。

这些检查不等同于真实账号登录验收。真实短信、扫码确认、平台风控及线上代理环境仍需用实际账号完成一轮登录与采集。

## 应用顺序

1. 先运行 `pnpm db:migrate`，应用 `0011_account_storage_state.sql`。
2. 配套更新并重启 API、Worker、Web；队列、登录锁及指令协议要求两端一致。更新前结束现有人工登录会话。
3. 对旧 DeepSeek 档案重新人工登录一次：旧 Cookie 无法补回此前未保存的 localStorage。新成功登录会清除旧冷却时间。
4. 分别验证豆包扫码/手机号和 DeepSeek 手机号登录，成功后触发一次采集确认可复用。

审查阶段仅在隔离测试库验证迁移。随后经用户授权已发布线上，见 [发布记录](./account-login-deployment.md)。
