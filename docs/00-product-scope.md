# 00 · 产品定位与范围

## 1. 产品定义

**GeoLens** 是一个面向品牌方与代理公司的 **AI 搜索品牌可见性监测平台**（GEO = Generative Engine Optimization 领域的监测工具）。

核心价值主张：

1. **看见**：用中立账号向主流 AI 引擎批量提问，量化品牌的提及率、推荐位次、口碑倾向与引用来源；
2. **可信**：每一条数据都能回放到原始回答、截图与采集过程记录，指标口径（分子/分母）全程透明；
3. **可行动**：把监测数据转成问题分层、缺口定位与优先级行动建议，输出可直接交付客户的诊断/周报/月报。

目标用户：

| 用户 | 场景 | 关键诉求 |
|------|------|----------|
| 品牌方市场/GEO 运营 | 持续监测自家品牌在 AI 搜索中的表现 | 每日数据、趋势、口碑风险预警 |
| 代理公司（Agency） | 多品牌代运营、给客户提案汇报 | 多品牌工作区、白标报告、数据口径可自证 |
| 新品牌/投标前摸底 | 单次诊断，无需订阅 | 按次付费、快速出报告 |

技术实施：全栈 Node.js（TypeScript）+ PostgreSQL，部署于阿里云 SAE；网页端采集经无影 AgentBay 浏览器（Browser Use 镜像）以 CDP 接入。详见 [07 技术实施方案](./07-tech-plan-nodejs-aliyun.md)。

|------|--------|------|------|

## 3. 裁剪带来的连锁设计调整

裁掉"发稿 + Agent"后，产品从"闭环平台"退守为"纯监测与洞察工具"。连锁调整：

1. **洞察建议规则化**：竞品原本由 Agent 生成优化建议，我们改为**确定性规则引擎**——基于三率漏斗与引用源缺口，输出 P0/P1/P2 行动建议表（规则见 02 文档 §6）。这更稳定、可解释，也避免了"AI 建议不可控"的问题。
2. **引用源洞察价值前置**：没有发稿闭环后，"信源平台偏好 + 引用缺口热力图"成为告诉用户"预算该往哪投"的核心输出，需在 M1 做扎实。
3. **报告成为留存抓手**：原产品的续费动力一部分来自发稿 ROI 归因，我们只能靠"周报/月报交付物 + 趋势资产"驱动续费，报告模板的投入要加大。
4. **积分用途收窄**：单次诊断、数据导出（Excel/报告 PDF）、APP 端加查等按量动作走积分；不存在"按稿件计费"。

## 4. 从竞品实测中吸取的 6 个教训（本产品必须规避）

以下问题来自对参照产品的实际走查与试用，属于"复刻神"必须解决的部分：

| # | 竞品的问题 | 我们的设计对策 |
|---|-----------|---------------|
| 1 | 自家产品（如 SU7/YU7）被当成"最强竞品"——识别词默认不做别名归一 | 品牌初始化时 AI 自动建议识别词+别名清单（从品牌简介、产品线中抽取），人工确认后生效；竞品列表同样自动建议 |
| 2 | 报告页品牌头图显示"0 监控问题/暂无采集"，与排名页实时数据不一致（基于凌晨日快照） | 单一事实源：所有卡片实时查询 + 明确标注数据时间戳；日快照仅用于趋势口径 |
| 3 | 统计周期默认"昨日"，新用户首屏全是 0 | 周期选择器自适应："今日（含进行中轮次，标注'部分数据'）" → "最近完成日" → 引导态 + 预计完成时间（口径见 02 §8） |
| 4 | 排名词/口碑词类型隔离隐蔽，配满排名词后口碑模块不可用 | 问题创建时即强制分类（排名词/口碑词），配额按类型分开显示；采集配置页实时显示两类占比 |
| 5 | 采集失败/配额耗尽被记为"无数据"，用户误读为"没人提" | 任务级状态机：成功/空回答/采集失败/配额拦截 四态分离，指标分母只计成功+空回答 |
| 6 | 引用源提取远慢于排名提取，空态无解释 | 管道分级：排名提取实时（分钟级），引用提取异步（小时级）；引用页空态显示管道进度与预计时间 |

## 5. 命名与合规红线

- **产品名、模块名、文案、报告版式、图标、配色全部原创**。竞品的"透镜""循证写作""信源阵地热力图"等命名与文案一律不用，改用自有命名（见 01 文档命名对照表）。
- **不复制**竞品官网任何文章、FAQ 文本、报告内容、llms.txt。
- "提及率、Top3 推荐率、首位推荐率、平均排名、情绪得分"等为行业通用指标概念，可使用，但**口径定义、阈值、计算规则写自有版本**。
- 采集手段存在违反目标平台用户协议的风险，法务评估与风险缓解见 06 文档 §4。
