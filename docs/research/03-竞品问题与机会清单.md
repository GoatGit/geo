# 调研存档 03 · 竞品问题与机会清单（决策依据汇总）

> 汇总两轮走查/实测中发现的竞品缺陷、设计启示与可借鉴模式，作为 GeoLens 设计决策的证据库。
> 详细证据见 [01 走查报告](./01-官网与控制台走查.md)、[02 实测报告](./02-小米汽车数据功能实测.md)。
> 设计对策已落入 [00-product-scope §4](../00-product-scope.md) 与各设计文档，本文保留完整证据与补充观察。

## A. 缺陷清单（我们的机会点）

| # | 缺陷 | 证据位置 | 对用户的影响 | GeoLens 对策（已入设计） |
|---|------|----------|--------------|--------------------------|
| A1 | 自家产品（YU7/SU7）被列为"最强竞品" | 实测 §6 | 竞品口径失真，榜单不可信 | 识别口径管理升级为一级模块；初始化 AI 建议别名并默认勾选自有产品线名；竞品发现强制排除本品口径 |
| A2 | 报告页品牌头图"0 监控问题/暂无采集"与排名页实时数据并存（凌晨日快照 vs 实时） | 实测 §9 | 用户怀疑数据丢失/系统坏了 | 单一指标服务供数；卡片级"数据截至"时间戳；实时/日结徽章（02 文档 §8） |
| A3 | 统计周期默认"昨日"，新用户首屏全 0 | 实测 §5.1 | 首次体验受挫，误以为功能坏了 | 周期选择器自适应："今日(进行中)"→"最近完成日"→引导态+预计完成时间 |
| A4 | 排名词/口碑词隐性隔离：8 配额被排名词占满后口碑模块不可用，加口碑词触发升级墙 | 实测 §8 | 付费用户感觉"买的功能用不了" | 问题创建时强制分类+分池配额显示；采集配置页常驻两类占比环 |
| A5 | 空数据口碑页显示红色"高风险"评级 | 走查 §7.4 | 零数据被误读为危机 | 空态/数据态严格分离；无数据显示引导而非结论 |
| A6 | 引用源提取滞后于排名，空态无解释（"今日暂无新增收录"） | 实测 §7 | 用户以为引用功能失效 | 管道分级+空态显示管道进度与预计时间（05 文档） |
| A7 | 采集失败/配额耗尽可能与"无数据"混淆 | 走查 V2.8.0 公告间接印证（历史口径问题） | "没人提我"与"没采到"不可区分 | QueryRun 四态状态机，failed/quota_blocked 不进分母且处处可查（02 文档 §1.1） |
| A8 | 登录页对记忆手机号自动发送验证码 | 走查 §3 | 无感知消耗短信、被打扰 | 显式点击后才发送 |
| A9 | 免费版配额 3 但示例品牌预置 8 问题，首屏即"8/3 超限"红条 | 走查 §9 | onboarding 与商业化压迫感冲突 | 配额与预置内容一致性校验；超限用非阻断式引导 |
| A10 | 积分语义混乱：订阅"解锁"发稿/AGENT，但余额 0 时按钮静默禁用 | 实测 §8 | "付了钱还是用不了"的抱怨点 | 积分消耗入口显式标注数值；余额不足给出获取路径而非仅禁用 |
| A11 | 前端细节：活动公告图裂、表格列竖排溢出、滚动白屏块、定价页重复渲染 | 走查 §9 | 精细度信任损耗 | 常规工程质量要求 |
| A12 | 排名榜同类目实体重复（"小鹏 P7+"与"小鹏 P7+ 725 Max"同时上榜） | 实测 §5.3 | 榜单条目虚高，竞品口径失真 | 05 §2 实体切分去修饰词 + 识别口径别名归一（已设计）；未匹配变体进竞品发现待确认池兜底 |

## B. 可借鉴的模式（值得学）

| 模式 | 竞品做法 | 我们如何内化 |
|------|----------|--------------|
| 实时采集队列可视化 | 排名透视页滚动显示"正在请求某引擎「某问题」"，完成打勾 | 保留并强化：独立"采集状态"页 + 总览页磁贴 + WebSocket 进度；队列健康度（账号池状态摘要）公开给用户 |
| AI 初始化进度叙事 | "正在搜索「品牌 竞品 …」"逐条打勾，产出档案+竞品建议 | 同样做法；但我们增加"识别口径确认"步骤（A1 对策），把口径主权交给用户 |
| 问题拓写确认页 | 短词→自然问法，逐条可编辑、字数计数 | 保留；增加类型分类确认（排名词/口碑词） |
| 分子/分母 tooltip | 指标卡 tooltip "09-14 首位率: 58% 分子/分母: 23/40" | 保留并升级为全局"口径徽章"组件（含 excluded 失败/拦截数） |
| 印象词"巩固 vs 攻坚"对照 | 正面词与负面词左右对照，中间出现次数，附口径说明（种数≠次数） | 借鉴布局思想，自有命名"优势印象/待攻印象"，必须附原文摘录证据 |
| 体检阈值公示 | 报告页直接写出健康阈值（提及≥85/前三≥60/…） | 保留；阈值改为品牌级可配置，并在报告方法论附录中说明依据 |
| 行动建议表格 | P0/P1/P2 × 动作 × 数据依据 × 目标 | 保留结构；由规则引擎生成（确定性、可复现、规则版本入库） |
| 报告"逐条可回溯" | 引用源明细 80 条，每条可点开原链接 | 保留并绑定证据包（原文/截图/录屏/哈希），7 天保留+到期提醒 |
| 按次诊断估价器 | 问题数×引擎×终端实时积分估价 | 保留；所有积分入口显式标价（A10 对策） |
| 识别词修改次数上限 | 识别词限改 3 次 | 借鉴其防滥用思想，但我们把修改成本前置到"确认"环节，确认后不设硬上限（口径变更走版本化） |

## C. 竞品的强项（不可轻视，需正面应对）

1. **出数速度**：配置完成约 5 分钟出 40 条真实查询，首次体验闭环极快 → 我们的 M0 验收线定为"≤10 分钟"。
2. **数据规模叙事**：日均 5 万+ 提问、3000 万引用源沉淀 → 我们用"证据链完整性"对抗"规模叙事"。
3. **信源库 14.3 万家 + 发稿闭环**：被裁剪不做的部分，恰是其收入大头；我们的报告/行动清单需在"内容与渠道建议"上足够具体，弥补无发稿闭环的空白。
4. **品牌初始化质量**：AI 简介/竞品/竞争点归纳准确度高 → 我们用同级别 LLM 能力不难达到，但要加上 A1 的口径确认。
5. **引用源当日出数**：102 来源/715 引用当日可见（仅追溯明细滞后）→ 说明其引用抽取管道对"回答内引用卡"有即时通路；我们的即时抽取管道应包含引用卡的同步抓取，把 A6 的滞后范围压缩到"正文内散落链接"。
