# 引擎通道决策:文心与豆包(docs/14 §4/§5)

> 2026-09-19。基于 9 月生产事故记录的决策文档。结论先行:
> **文心=立即投入一次完整校准;豆包=短期降频+风控对抗,中期切官方 API。**

## 文心(chat.baidu.com)——校准窗口开启

### 现状
- UI 已迁移:wenxin.baidu.com 提问 → 跳转 chat.baidu.com 搜索结果页(全新 DOM)。
- 旧选择器靠兜底碰运气;9/18 曾单日恢复 32 条成功(说明通道可用),9/19 又遇 wappass 图形验证码墙。
- 游客提交被风控概率高;登录态(BDUSS)下未验证。

### 决策:投入一次完整校准(预计 0.5–1 天)
1. 人工登录一个文心档案(用户提供 BDUSS)。
2. 用 cdp-wenxin-cite-check.js(已备)在登录态下 dump:输入框/发送/回答容器/引用面板结构。
3. 更新 sites.ts 的 wenxin 配置(新域名 chat.baidu.com + 新选择器 + minAnswerChars)。
4. 引用抽取:新 UI 的信源走搜索结果卡,大概率需复用网络收割器(白名单 chat.baidu.com 的 search API)。
5. 验收:连续 10 题成功 + 引用出数。

**不做校准的备选**:若 2 周内无资源,把 wenxin 从 WEB_ENGINES 默认面移除,引擎位标注"维护中",
避免"5 引擎覆盖"的虚假承诺(docs/14 §5)。切换开关建议做成 platform_settings 而非改代码。

## 豆包——分阶段

### 现状(9 月实测)
- 风控软拦截失败率 ~50%,三种形态:推荐位空回答(58 字符)/ 输入框消失(local_ 会话)/ goto 超时。
- minAnswerChars=120 门槛已把垃圾回答挡为 failed(正确);真实成功时引用走 SSE 流式嗅探(已通)。
- 拦截与 IP/会话年龄/频率相关,当前无稳定绕过。

### 决策
- **短期(本周)**:降频——豆包每档案日上限从 20 降到 8(engineDailyCaps 可配,无需改码);
  失败形态自动归类埋点(推荐位/输入框/超时三分支已有 error 文案,统计入 admin)。
- **中期(1 个月内)**:评估火山方舟官方 API(豆包 chat API 按 token 计费,无风控/浏览器成本)。
  评估点:答案风格与 Web 端一致性(引用来源结构)、单 token 成本 vs DOM 采集、合同合规。
  若一致 → 豆包通道整体切 API,DOM 仅作兜底。
- **长期**:DOM 采集保留给无 API 的引擎(元宝/文心),形成"API 优先、DOM 兜底"的双通道架构。

## 引擎通道健康月检(新增运营动作)

每月核对:各引擎成功率/失败形态分布/UI 改版监控(sites.ts 选择器版本 vs 实际 DOM 抓样)。
四引擎中任何一个连续 3 天成功率 < 30% → 自动告警(已上线 Alerter.breakerTripped)。
