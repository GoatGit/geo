## 2. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端 | Next.js 14 + TypeScript + TanStack Query + shadcn/ui + ECharts | 数据密集型工作台，组件可控可换肤 |
| BFF/API | NestJS (Node 20, TS) | 与前端同语言，模块化清晰；团队熟悉度优先可换 Go |
| 核心服务 | NestJS 单体优先，按模块分包（用户/监测/指标/报告） | 初期避免微服务化过早，模块边界清晰留拆分余地 |
| 采集 Worker | **独立进程池，Node 22**；网页端 playwright-core 经 CDP 连 AgentBay Browser Use 会话；APP 端(P1)评估 AgentBay 云手机 | 无状态 Worker 与远程浏览器解耦，可独立伸缩；落地见 07 v2 |
| 编排/队列 | BullMQ(Redis)（起步）→ Kafka（日任务 > 50 万再迁） | 消费组/ACK/延迟重试开箱即用，Node 生态原生 |
| 业务库 | PostgreSQL 16 | 事务 + JSONB（回答原文）+ 分区表（QueryRun 大表） |
| 指标聚合 | 初期 PG 物化视图；P1 引入 ClickHouse | 日任务量大后聚合查询成本陡增时再迁移 |
| 对象存储 | S3 兼容（MinIO 自建 / 云 OSS） | 截图、录屏、导出文件 |
| 缓存/锁 | Redis | 配额计数器、分布式锁、进度推送 |
| LLM | 国产模型 API（解析/抽取/拓写），可多供应商路由 | 成本与合规；解析类任务用小模型 |
| 部署 | **SAE**（geo-web / geo-api / geo-worker 三应用，指标+定时弹性，staging 缩零） | 免节点运维、按量秒级计费；详见 07 v2 |

## 3. 服务职责边界

### 3.1 监测服务（Monitor Service）
品牌/问题/识别口径/采集计划的 CRUD；配额校验（问题数、引擎端、频率）；把"采集计划 + 轮次调度"翻译成 QueryRun 任务流写入队列。

### 3.2 采集编排器（Orchestrator）
- **Roster 生成**：每日轮次触发（cron per 品牌）→ 展开 `问题 × 引擎 × 端` 为 QueryRun → 按品牌优先级入队。
- **调度约束**：账号池并发上限、引擎侧限流（每引擎 QPS/每小时配额）、同品牌任务打散（避免同一账号连续问同一品牌——拟人化）、失败重试策略（指数退避，最多 2 次，重试换账号换出口 IP）。
- **状态回写**：任务状态机流转 + WebSocket 广播进度（前端队列面板）。
- **熔断**：引擎连续失败率 > 阈值时自动暂停该引擎派发并告警（防止"接口配额耗尽→整轮全空"事故，教训 #5）。

### 3.3 采集 Worker
执行单条 QueryRun：领取账号会话 → 注入问题 → 等待回答完成 → 落盘回答原文/截图/录屏 → 上报结果与元数据。**Worker 不理解业务指标**，只负责忠实采集与存证。

### 3.4 抽取管道（Extraction Pipeline）
消费 `query_run.completed` 事件：解析回答 → 结构化抽取（提及/位次/引用/印象词）→ 写入口径事实表 → 触发指标增量更新。排名类抽取实时同步做（毫秒-秒级规则 + 轻模型），引用与印象词异步排队（分钟-小时级，LLM 批处理）。

### 3.5 指标服务（Metrics Service）
唯一聚合口径出口：三率/漏斗/体检/竞品榜/行动清单。输入=口径事实表，输出=各页面/报告的指标 DTO。**禁止其他服务直连原始表聚合**（教训 #2 的制度保障）。

### 3.6 报告服务
周/月 cron 触发生成 → 从指标服务拉取周期 DTO → 渲染报告（HTML 模板 → PDF）→ 存储 + 通知。快速体检走同管道，模板不同。

## 4. 关键横切设计

- **鉴权**：JWT + RBAC（账号级角色；品牌级隔离在数据层强制 `brand_id` 作用域）。手机验证码登录接入国内短信服务商 + 频控。
- **配额与计费**：所有写操作经"配额检查器"（Redis 原子计数），扣积分走事务 + 流水表。
- **审计与可回溯**：QueryRun 保留请求元数据哈希（账号指纹、出口 IP、时间戳、引擎页面版本），快照文件带内容哈希，构成证据链。
- **可观测性**：OpenTelemetry traces（一次 QueryRun 跨编排/Worker/抽取全链路）、Prometheus 指标（各引擎成功率、账号池健康度、队列深度）、关键告警（引擎成功率骤降、账号封禁速率、队列积压）。
- **多环境**：dev（Mock 引擎适配器，回放录制的回答）→ staging（真实引擎小流量）→ prod。

## 5. 性能与容量目标（首年）

| 项 | 目标 |
|----|------|
| 单轮采集（8 题 × 5 引擎 = 40 QueryRun） | ≤ 10 分钟完成 |
| 首年日增 QueryRun | 5 万（500 品牌 × 100 查询均值） |
| QueryRun 表 | 按月分区，原始回答 JSONB 冷数据 12 个月后转对象存储 |
| 指标查询 P95 | < 500ms（实时页） |
| 采集 Worker | SAE geo-worker 起步 1-2 实例（1vCPU/2G）；AgentBay 并发会话 M0 ≤10 → Pro 档 ≤200 |
